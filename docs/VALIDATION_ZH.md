[English](VALIDATION.md)

构建目标：Apple Silicon，macOS 13.0 或更高，版本 1.0（7），使用 macOS SDK 27.2 和 Swift 6.4.2。

## 已完成检查

构建 7 修复原生模式缓存刷新及后台锁定恢复，本轮执行了原生模式、锁定和显示器模型套件。未改动的选择、布局和 EDID 证据沿用其最近一次相关验证。

- 8 组显示器选择回归覆盖每次打开定位、保留手动选择、断开不替换目标、目录迟到、CG ID 复用、歧义与不支持的屏幕、负原点、菜单栏顶边、上下相接屏幕，以及打开中跨屏切换。
- 只读 AppKit 与目录探针发现 3 个具有唯一系统 ID 的屏幕，全部精确匹配目录，未输出名称、ID 或坐标。此检查不能代替真实多屏菜单栏点击验收。
- 界面源码复核覆盖精简文案、当前模式及操作反馈只展示一次、次要显示器菜单、长文本换行及禁用条件保留；同名菜单项仍按稳定身份区分。
- 8 组显示器模型回归：时序缺失、记录残缺和冲突、模式身份、旧偏好和 EDID 唯一匹配。
- 7 组原生连接模式回归：完整位宽 ID、精确时序兼容、最新身份和目标核验、重复回读及修改互斥；Objective-C 模拟对象新增覆盖当前模式和可用列表缓存过期、同一对象重复刷新，以及刷新方法缺失或 ABI 不符时在读取缓存前拒绝快照。
- 33 组模拟后端锁定回归覆盖持久化、兼容性、身份、退避、共享互斥及逐屏电源和会话恢复。新增用例覆盖不手动调用恢复函数的真实后台调度、长时间锁屏、连续刷新、启动时锁定目标离线、目录恢复、重连后自动与手动暂停的区别、读取失败不重开预算、写入中暂时断开，以及另一台显示器在写入期间重连。测试使用隔离偏好，不调用真实 setter。
- 旧桥接在缓存过期模拟中失败；旧调度在无通知的及时恢复测试中失败；旧生命周期在确认重连后无法解除自动暂停。三项回归修复后均通过。这些是受控代码复现，不是实际熄屏唤醒测试。
- 缺少唤醒通知的回归在旧实现中失败：反复读取已经亮起且可写的显示器，仍因休眠标记未清除而没有恢复。新实现通过电源及会话状态校准通过该用例。这里复现的是代码缺陷，不是用户的真实锁屏硬件过程。
- 12 项面板几何检查：不同屏幕原点、窄屏和低高度可用区、无效尺寸，以及显示期间只允许安全缩小。
- 5 组原生 Swift EDID 回归；3 份合成数据与 Python 输出逐字节一致。
- 8 项 Python EDID 测试，覆盖扩展保留、偏移、校验和及 override plist 结构。
- 8 组无特权安装脚本测试：有无原文件的安装恢复、外部改动、符号链接、特殊路径字符、备份损坏和排他锁。
- 安装脚本只在临时测试目录中执行。管理员 AppleScript 已编译检查，未执行。
- 只读目录探测发现 3 台外接显示器，并取得唯一匹配的 EDID。两台提供当前驱动时序，另一台提供支持时序但缺少当前时序 ID。
- 原生只读探测在 3 台显示器上均取得实时模式和兼容设置候选；仅检查 setter 签名，没有调用。
- 最终优化 arm64 应用已编译并通过 ad hoc 签名校验，包含英语和简体中文资源。Mach-O 的 SDK 版本显式链接为 27.2，与最低部署版本 macOS 13.0 分开。

## 实现复核

- BetterDisplay 5.1.1 静态分析及独立只读运行时探针确认了 CADisplay 通道，详见[实现依据](PRIVATE_DISPLAY_API_ZH.md)。
- 界面参考 EC25 的原生面板：固定画布、内部滚动、系统分组和控件、可选择技术参数；没有宣称截图或外观已验收。
- 支持的操作均有实际处理路径，不支持的模式没有应用动作；等待、不可用、冲突和未确认状态分别呈现。
- 面板顺序为色彩模式切换与锁定、安装配置、应用设置及关于。新系统使用原生玻璃控件和滚动边缘效果，macOS 27 使用 item-based alert；关于打开系统标准面板，旧系统保留兼容控件。
- 显示器名称只在顶部展示一次，当前模式不再列入替代选项，锁定正常状态不常驻解释段落。导出、改写计数和路径合并到配置详情；读取时间位于显示器详情，退出移至应用设置并保留快捷键。
- 使用公开 AppKit 显示器 ID 和点击来源定位。右键“打开”的来源随菜单项保存；非鼠标入口才使用窗口锚点回退。镜像或无法匹配来源时，不静默选择其他目标。
- 唤醒恢复使用独立的有界只读复查循环，并逐屏判断就绪状态。主队列的睡眠、唤醒及会话回调同步进入 MainActor；未知会话读数不会创建新的恢复周期，自动暂停与手动切换未确认的暂停分开处理。
- 启用锁后另以每秒一次的轻量检查核对拓扑和连接，完整目录在无变化时保持 20 秒刷新。CoreGraphics 回调只异步安排读取；连续刷新保留最早的恢复时间。明确重连可重开自动预算，读取失败或目标自身写入期间的暂时断开不可重开预算。
- 每次原生快照、写入预检和确认回读均先通过已校验的 `update` 方法刷新 CADisplay 缓存。固定匿名状态和暂停原因使用 notice 级别留存，不记录显示器身份或模式参数。

## 人工验收

1. 在各显示器点击菜单栏图标，核对标题及参数；A 屏面板打开时点击 B 屏图标，应同次切换到 B；右键“打开”应跟随最初右键所在屏幕。外框保持固定，内容内部滚动。
2. 手动选择其他显示器后，等待刷新确认不会被拉回；关闭后在另一屏重新打开，自动选择应恢复。检查断开、镜像、长名称、同名显示器、小屏钳制、两种语言、外观及键盘操作，不能把无关显示器变成隐式目标。
3. 确认不支持应用的模式保持可读且不可操作。应用一个兼容原生模式，检查等待状态，并将回读格式与请求对比；两次一致才可确认，超时不能报告成功。WindowServer 保存记录不能被标为实时测量。
4. 选择所需当前模式后再开启“锁定色彩模式”。锁屏并等显示器实际熄灭，再亮屏解锁；等待就绪状态结束后核对保存目标、锁定状态和实时模式。另检查亮屏后停留锁屏页超过一分钟再解锁、自动暂停后断开重连，以及多显示器中部分屏幕仍休眠的情况。关闭开关应停止后续恢复；不兼容时序应保持等待，未确认的手动切换不应马上被旧目标拉回。
5. 先导出 EDID override，核对修改摘要和文件位置。安装或恢复需要明确确认及 macOS 管理员授权；如要单独观察 EDID 效果，先关闭模式锁定。
6. 安装或恢复后重新连接显示器，检查实际输出。文件安装成功不能证明 RGB Full Range 已生效。检查面板末尾的应用设置和标准关于面板。

2026-10-29 的只读探针确认：有一个已开启的锁，目标唯一、可写且时序兼容，实际系统模式仍与目标不符。正常退出原构建 6 进程后启动构建 7，未修改已保存目标。新版自动恢复该既有锁定目标：匿名日志从东八区 19:36:48.531 的 `retryScheduled` 进入 `restoring`，于 19:36:50.729 完成 `confirmed` 和 `matching`，距首条状态记录约 2.2 秒。独立刷新回读随后确认一个锁已匹配、零个待恢复目标，三台显示器均已唤醒且原生模式可读。此结果是一次启动恢复观测，不是通用延迟保证。

本轮未点击菜单栏、截图、执行管理员安装、触发锁屏熄屏或手动请求模式切换。真实 setter 仅由重启后的应用根据用户已开启的锁自动调用。已观察到系统层恢复及回读确认；真实熄屏唤醒恢复、视觉、多屏交互、管理员流程和 HDMI 信号验收仍待完成。

```bash
scripts/test.sh

```
